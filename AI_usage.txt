2. Debounce-Mechanismus mit useEffect
Für City Input:
useEffect(() => {
  const timer = setTimeout(() => {
    setDebouncedCityInput(cityInput);
  }, 1000);
  
  return () => clearTimeout(timer);
}, [cityInput]);

Für Postal Input:
useEffect(() => {
  const timer = setTimeout(() => {
    setDebouncedPostalInput(postalInput);
  }, 1000);
  
  return () => clearTimeout(timer);
}, [postalInput]);

Wie funktioniert das?

Jedes Mal, wenn sich cityInput oder postalInput ändert, wird ein Timer gestartet
Der Timer wartet 1 Sekunde (1000ms)
Wenn innerhalb dieser Sekunde eine neue Eingabe erfolgt, wird der alte Timer gelöscht (cleanup function clearTimeout)
Ein neuer Timer startet von vorne
Erst wenn 1 Sekunde ohne neue Eingabe verstreicht, wird der debounced Wert aktualisiert
3. API-Aufrufe werden durch debounced Values getriggert
Die Logik für API-Calls wurde aus den onChange-Handlern in eigene useEffect-Hooks verschoben:

Vorteile des Debouncing:
✅ Weniger API-Requests: Statt bei jedem Tastendruck wird nur 1x nach Ende der Eingabe die API aufgerufen
✅ Bessere Performance: Weniger Netzwerktraffic und UI-Updates
✅ Bessere User Experience: Keine flackernden Ergebnisse während des Tippens
✅ Server-schonend: Reduziert die Last auf der API

Beispiel: Wenn ein Benutzer "München" eingibt, werden nicht 7 API-Calls (M, Mü, Mün, Münc, Münch, Münche, München) ausgeführt, sondern nur einer – 1 Sekunde nach dem letzten Buchstaben.
